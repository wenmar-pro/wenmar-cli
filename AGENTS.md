# Wenmar CLI

Go CLI for the Wenmar Pro automotive shop management API. Single static binary built with Cobra; TUI via bubbletea/lipgloss. Consumes the Go SDK from the wenmar-sdk repo.

## Commands

```bash
make build            # build ./wenmar
make test             # go test ./... -v
make check            # build + tests + SDK drift check (also runs ../wenmar-sdk/go tests) + smoke
make check-published  # verify against the published SDK tag, bypassing local go.work (GOWORK=off)
make generate         # regenerate cmd/gen_*.go from the enriched OpenAPI spec (needs ../wenmar-sdk)
make golden-update    # refresh committed golden fixtures (regen-drift gate)
make surface-snapshot # rewrite surface-snapshot.json after intentional command-surface changes
make surface-diff     # fail if the command surface changed without a snapshot update
```

Race-detector CI runs `go test -race ./...`. Linting is golangci-lint (`errcheck`, `govet`, `staticcheck`, `unused`) plus `gofmt`, `go vet`, `govulncheck`, and shellcheck on `install-cli`.

## Architecture

- **Generated commands**: resource commands are generated by `cmd/gencli` (dave/jennifer) from `../wenmar-sdk/spec/openapi.enriched.yaml` into committed `cmd/gen_*.go` files, sharing runners in `cmd/runners.go`.
- **Golden rule: never hand-edit `cmd/gen_*.go`.** Change the generator (`cmd/gencli/`), the overrides (`cmd/gen_overrides.yaml`), or the spec source, then `make generate`.
- **Non-derivable commands** live in companion files: `customers_extras.go`, `vehicles_extras.go`, `wo_extras.go`, `wo_technicians.go`.
- **Drift gates**: `make golden-update` fixtures, `surface-snapshot.json`, and `docs_freshness_test.go` (validates documented CLI invocations in `skills/wenmar/SKILL.md` and `README.md` against the real command tree).

## Cross-repo coupling (critical)

- `go.work` includes `../wenmar-sdk/go` — local builds/tests use the sibling SDK checkout.
- `SPEC_PATH` defaults to `../wenmar-sdk/spec/openapi.enriched.yaml`.
- `make check` runs the SDK's Go tests in `../wenmar-sdk/go`.
- The spec itself is pushed from wenmar-pro CI; it is read-only here.
- Full pipeline docs: load the `sdk-cli` skill from `wenmar-pro/.opencode/skills/sdk-cli/SKILL.md`.

## Multi-Agent Worktree Workflow (Critical)

AI agents run in parallel on this machine (herdr terminal runtime). One agent = one worktree = one herdr workspace. The main checkout is **user-only**.

- **Worktrees are created as SIBLING directories**, not under `.worktrees/`, so the relative `../wenmar-sdk` paths in `go.work` and the Makefile keep resolving: `bin/worktree create <task-name>` creates `../wenmar-cli-<task-name>`.
- **Never edit files in the main checkout.**
- **One agent, one repo**: never work on wenmar-cli and wenmar-sdk simultaneously — the CLI's go.work consumes local SDK changes instantly.
- **Finishing**: commit ALL work, report back, and hand to the user for `bin/worktree merge <task-name>`. Never merge, push, or delete branches yourself.
- Full manual: `~/Projects/wenmar-pro/docs/herdr-multi-agent.md`
